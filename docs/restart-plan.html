The product contract

Stable surface

Dashboard

A fully editable grid for pinned apps and widgets. Nothing moves automatically. Exact positions and spans survive process death and reboot.

Adaptive surface

Category pages

Local metadata and maintained rules generate categories. Manual overrides always win. Optional usage access reorders apps only within a category.

All-apps drawer

A conventional near-full-screen grid with deterministic search across labels, packages, and categories. Work-profile identity remains visible.

Guided first run

Preview first, explain optional usage access, then request the HOME role only after explicit action. Discovery failure blocks the role prompt.

Implementation sequence

Normalize the baseline

  • Align the checked-in Gradle/Compose configuration without speculative upgrades.
  • Keep the product brief, implementation status, and this ledger honest.
Sync + build

Domain and persistence

  • Introduce profile-safe app identity, category IDs, grid positions/spans, dashboard items, explicit load states, and repository contracts.
  • Add atomic versioned workspace writes, last-good recovery, and migration from the widget-only schema.
  • Make preferences Flow-backed and bounded.
Unit gate

Discovery, ranking, and categories

  • Conflate package refresh events, keep last-good data, and do platform work off the main thread.
  • Detect usage permission through app ops; rank within categories with deterministic ties.
  • Apply override, Android metadata, exact rule, prefix rule, system rule, then Other.
Device gate

Static Compose states

  • Preview onboarding, dashboard, edit mode, drawer/search, categories, work profile, permissions, failures, recovery, dark mode, large font, portrait, and landscape.
  • Obtain Monroe’s preview approval before broad behavior wiring.
Visual gate

Dashboard editing

  • Build a pure placement engine, then pin, drag, resize, remove, reject invalid drops, and restore.
  • Commit only valid placements; revert on persistence failure.
Device gate

Complete widget lifecycle

  • Allocate, pick, bind, configure, preview, place, persist, resize, remove, reconcile, and restore.
  • Delete allocated IDs on every canceled or rejected path. Use repair/remove placeholders for stale providers.
3 providers

Drawer, categories, and settings

  • Finish deterministic search, long-press actions, category overrides, Back priority, and stable active interactions.
  • Apply settings reactively; preview and confirm grid reflow that displaces items.
UX gate

Integrated launcher and release

  • Validate onboarding, HOME role, package changes, permission revocation, process death, reboot, recovery, configuration changes, and accessibility.
  • Smoke-test the exact installed release artifact.
Release gate

Required truth states

Apps

Loading, Ready, Degraded with last-good data, and Failed. Discovery failure must never silently become an empty launcher.

Workspace

Loading, Ready, and Recovery required. Corrupt data remains available for diagnostics until reset or successful migration.

Usage access

Denied or revoked means deterministic alphabetical fallback, not a broken launcher and not repeated nagging.

Unavailable items

Removed apps and widget providers become explicit removable or repairable placeholders instead of crashes or unexplained disappearance.

Defaults locked for implementation

  • Android 13/API 33 minimum; compile and target SDK 36.
  • Local deterministic categorization; manual overrides always win.
  • Usage ranking affects category order only; dashboard placement is never automatic.
  • Full dashboard grid editing and complete widgets are V1 requirements.
  • The HOME role follows a guided preview and explicit user action.
  • Android Studio and Monroe’s physical device are the visual and installation authority.
  • No failed workflow, provenance, build, persistence, or device gate is bypassed silently.
